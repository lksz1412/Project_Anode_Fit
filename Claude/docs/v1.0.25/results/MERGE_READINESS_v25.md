본 서브세션이 계수하는 동안 마스터는 `_sections` 편집을 **계속 진행하고 있었다**. 보고서 mtime(**02:06:22**)
이후에도 4파일이 수정됐다:

| 파일 | mtime | 보고서 기재 | 02:25 재계수 |
|---|---|---|---|
| `ch1_sec06_eqpeak.tex` | 02:08:44 | +38 | **+39** |
| `ch1_sec05b_gr2L.tex` | 02:09:21 | +39 | **+42** |
| `ch1_sec18_inputs.tex` | 02:11:33 | +22 | +22(줄 수 동일 · 내용 수정) |
| `ch3v22_sec02b_sifr.tex` | 02:17:13 | +36 | **+39** |

| 대상 | 마스터 보고(02:06) | 본 서브세션 재계수(02:25 스냅샷) |
|---|---|---|
| 편집 파일 수 | 14 | **14**(일치) |
| 줄 증가 합 | **+250** | **+257**(02:10 스냅샷에서는 +254 — 계수 중에도 증가) |
| 신규/삭제 라벨 | +3 / −0 | **+3 / −0**(동일 집합, 일치) |
| `\boxed` | 38 → 39(구조 검사 기준) | `_sections` 원시 계수 60 → 61(**+1**, 증분 일치) |

**평가**: 구조적 결론(라벨·boxed·편집 파일 수)은 모든 스냅샷에서 동일하므로 **판정을 바꾸지 않는다.**
그러나 ① 마스터 보고의 줄 수가 최종값이 아니고 ② 정적 검사·doc↔code 감사가 그 편집 **이전** 실행분이라는
두 사실이 남으므로 **AMBER-2** 로 등재했다. → 마스터 확인: `+250` 을 편집 종료 시점 계수로 갱신할지.

필요해진 증빙). 분모 8 자체는 마스터 보고(8/8)와 일치한다 → **AMBER-3**.
